# Fork the Prize

## Why Every Organization Should Host Their Own Version

The prize mechanism is open source. The scorecard, the rules, the baseline bundle, the adjudication logic — all of it is published at prize.warondisease.org. Any organization can fork it and run their own version. We want you to. Here's why.

### The Network Effect

One prize creates one selection pressure. Ten forks create ten. A hundred forks create a market for governance reform that didn't exist yesterday. Each fork:

- Attracts different challengers (an XPRIZE fork attracts engineers; an EA Funds fork attracts economists; a university fork attracts researchers)
- Tests the mechanism in different contexts (country-specific, disease-specific, policy-specific)
- Produces challengers that compete across ALL forks, because the scorecard is standardized
- Improves the baseline for every other fork when a better module is found

This is the same reason open source software won. Not because any single contributor was the best. Because the selection pressure was distributed across thousands of independent actors, each one selfishly improving the thing for their own reasons.

### How to Fork

1. **Read the mechanism:** prize.warondisease.org
2. **Copy the scorecard.** All 28 metrics. Don't edit them — the standardization is what makes cross-fork comparison possible.
3. **Set your prize pool.** Any amount works. $10K attracts students. $1M attracts teams. $100M attracts institutions.
4. **Scope your fork** (optional). You can run the full bundle or focus on one module:
   - Medical throughput only (dFDA module)
   - Political adoption only (Incentive Alignment Bond module)  
   - Waste identification only (Efficiency Audit module)
   - Country-specific implementation (US, UK, India, etc.)
   - Disease-specific (cancer, Alzheimer's, rare diseases)
5. **Publish your fork.** Link it to the network. Every fork strengthens every other fork.
6. **Run it.** Accept challengers. Score them. Award the prize to whoever beats the baseline.

### The Meta-Property

Here is the part that should convince you:

If hosting a fork is a bad idea, a challenger will produce a better coordination mechanism and beat the fork on the scorecard. The fork then funds the better mechanism instead. You cannot lose by hosting a fork, for the same reason the prize itself cannot lose: the only way to beat it is to produce something better, and producing something better is the entire point.

A fork is a no-lose bet on the mechanism being a no-lose bet.
